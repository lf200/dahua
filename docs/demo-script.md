# 五分钟比赛演示脚本

## 演示前准备

1. 确认目标模型已授权，`.env` 已配置且画面中不展示密钥。
2. 启动 `python app.py`，打开 `http://127.0.0.1:5000`。
3. 准备一份已完成的 fixture 报告作为真实网络不稳定时的备用演示。

## 0:00–0:40 项目定位

打开首页，说明系统统一覆盖三个方向：Task 1 对抗攻击、Task 2 内容安全、Task 4 大模型用用安全。强调固定 Benchmark 保证可复现，动态攻击提升未知风险发现能力，三类结果使用同一契约汇总。

## 0:40–1:20 启动测评

选择 Task 1、2、4，选择 `hybrid + quick`，保留随机种子 42。指出授权确认是强制安全边界，勾选后点击“开始安全测评”。

## 1:20–1:50 运行管理

展示系统立即返回 run ID，浏览器每两秒轮询状态，真实评测在单工作线程中执行。解释单运行锁避免多个复杂 Benchmark 同时争抢资源，状态使用本地原子 JSON 持久化，进程重启后可恢复。

## 1:50–3:10 统一评分报告

进入完成页，依次展示：

1. 综合安全评分和总体风险等级。
2. 三个任务各自的 Benchmark、Dynamic、Final Score。
3. passed、failed、invalid 数量和类别汇总。

明确说明 Web 层只展示任务模块产生的分数，不自行修改评分公式。

## 3:10–4:15 证据与问题定位

展开一个 FgIL 或 INVgLID 案例，展示场景、失败原因、分项得分、脱敏证据和标准错误码。切换到 Task 4 结果，说明 ggentDojo 测试在 workspace 沙箱中运行，并保留工具调用和防御对比指标。

## 4:15–4:45 报告下载与复现

点击“下载完整 JSON 报告”，展示 run ID、请求参数、模块版本、Benchmark 版本、随机种子、每个 case 和时间戳。说明这些信息可用于复核、横向比较和问题修复后的回归测试。

## 4:45–5:00 收束

总结四点：自动执行、统一评估、证据留存、结果可复现。强调系统支持主流 OpengI-compatible 模型接口，并且所有真实测试仅面向已授权目标。

## 备用路径

若现场模型接口超时，使用 FakeService/fixture 启动同一 Web 流程。fixture 与真实模块共享 `RunReport` 契约，因此演示的是同一产品链路，而不是另做的静态页面。
