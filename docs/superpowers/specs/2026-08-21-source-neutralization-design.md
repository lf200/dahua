# 第三方来源中性化设计

## 背景与目标

当前仓库在配置键、Python 符号、文件名、运行报告、Web 展示、错误信息、测试夹具和内部文档中直接使用第三方安全测试框架的名称。这些名称越过了私有适配边界，使外部使用者能够从应用配置、接口或运行结果推断实现来源。

本次变更将所有自有代码和对外表面改为能力导向的中性命名，同时保留现有测评行为。第三方名称只允许出现在程序运行所必需的互操作位置，包括依赖声明、第三方导入、包版本检测和第三方规定的环境变量。

## 设计原则

1. 对外契约只描述系统能力，不描述底层供应商或框架。
2. 自有模块、类、字段和测试使用同一套中性术语，避免内部名称再次泄漏到异常、序列化结果或模板。
3. 第三方集成集中在私有适配器内，其他模块只依赖自有接口和数据模型。
4. 采用硬切换，不保留旧配置键、旧 JSON 字段或旧 Python 导入路径的兼容别名。
5. 不修改测评算法、评分规则、基准数据和任务选择逻辑。

## 统一术语

动态对抗与内容安全能力统一使用 `dynamic_test` / `DynamicTest` 前缀；隔离应用与工具调用安全能力统一使用 `application_security` / `ApplicationSecurity` 前缀。

主要映射如下：

| 范围 | 新名称 |
| --- | --- |
| 动态测试适配器文件 | `dynamic_test_adapter.py` |
| 动态测试适配器类 | `DynamicTestAdapter` |
| 应用安全适配器文件 | `application_security_adapter.py` |
| 应用安全适配器类 | `ApplicationSecurityAdapter` |
| 应用安全模型环境变量 | `APPLICATION_SECURITY_MODEL` |
| 应用安全模型设置字段 | `application_security_model` |
| 动态测试引擎标识 | `dynamic_test` |
| 应用安全引擎标识 | `application_security` |
| 应用安全指标字段 | `application_security_metrics` |
| 适配器版本证据字段 | `engine_version` |

## 配置与数据流

配置从 `.env` 的 `APPLICATION_SECURITY_MODEL` 进入 `Settings.application_security_model`，再通过 `RunContext` 传递到私有应用安全适配器。该配置未提供时回退到 `TARGET_MODEL`，与现有默认行为一致。

任务模块只能接收自有适配器返回的可序列化结果。模块将结果规范化为中性 `CaseResult`、证据和聚合指标；`RunReport`、JSON Schema、Web presentation model 与模板只认识中性字段。第三方对象和名称不得跨越适配器边界。

## 修改范围

需要同步处理以下自有资产：

- `.env.example`、README、演示文档、交接文档和历史计划；
- 核心配置模型及其公开摘要；
- Task 1、Task 2、Task 4 的适配器、模块、模型与解析代码；
- 公共契约、JSON Schema、模块清单、benchmark 元数据；
- Web 路由、presentation model、模板和 CSS；
- contract fixtures、单元测试、E2E 测试和测试文件名。

依赖清单、第三方导入、包版本检测和第三方规定的遥测环境变量保持原始技术标识，因为修改这些标识会破坏安装或运行。除此之外不设置兼容白名单。

## 错误处理与安全边界

缺少依赖、版本不兼容、模型不支持、动态生成失败和轨迹异常等错误继续保留原有类型与控制流，但消息改为中性描述，例如“动态测试引擎不可用”或“应用安全引擎版本不受支持”。错误、日志、状态文件、报告和页面不得包含第三方名称。

API Key、目标地址和运行目录的现有脱敏与路径约束保持不变。本次变更不扩大网络访问或被测目标范围。

## 兼容性

本次采用硬切换：旧环境变量、旧 Python 导入路径、旧 JSON 字段和旧 CSS 类不再支持。已有 `.env` 需要改用新键；旧运行报告不保证能够被新版 Web 页面加载。新版本生成的所有报告必须符合更新后的 schema。

## 验证策略

1. 为新配置键及其 `TARGET_MODEL` 回退行为补充配置测试。
2. 更新各任务模块、契约、schema、presentation 和 E2E 测试，验证中性字段贯穿完整数据流。
3. 运行完整 `pytest`，确保测评和 Web 行为保持一致。
4. 对所有受 Git 管理的文本文件运行大小写不敏感的禁词检查。
5. 禁词检查只允许在依赖声明、第三方导入、包版本检测和必要环境变量所在行命中；所有其他命中均视为失败。
6. 检查 `git diff --check`，并审阅重命名结果，确保没有重复模块、陈旧导入或旧测试文件残留。

## 非目标

- 不替换或重写第三方框架本身；
- 不改变 benchmark 内容、动态攻击集合、评分公式或超时预算；
- 不提供旧配置和旧报告迁移层；
- 不通过隐藏或篡改必要的软件依赖信息来伪装供应链。
